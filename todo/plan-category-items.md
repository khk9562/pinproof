# 이슈 → 카테고리 + 항목별 완료 계획

> 2026-10-20 · 브랜치 `feat/category-items`

## 목표

"기록 하나 = 이슈 하나(증거 A·B·C)" 구조를 **"카테고리 안에 항목이 쌓이고, 항목마다 완료 여부를 갖는"** 구조로 바꾼다.
에이전트가 항목을 처리하고 완료 표시를 남기면, 사이드 패널이 그것을 읽어 바로 보관한다.

## 확정된 결정 (2026-10-20, 사용자)

| # | 질문 | 결정 |
|---|---|---|
| 1 | 항목 표기 | A·B·C → **숫자**. 폴더 전체에서 한 번만 쓰는 번호(#13), 기존 기록의 마지막 번호 다음부터 |
| 2 | 묶음 | 이슈 대신 사용자가 만드는 **카테고리**(데이터 정합성, UI·UX 개선, 버그 …) |
| 3 | 완료 | 에이전트가 `status: 완료`로 바꾸면 패널이 **바로 보관**. 보관함에서 **되돌리기**(상태는 대기로) |
| 4 | md 단위 | (위임) **항목 하나 = md 하나** `.pinproof/items/013.md`. 카테고리는 frontmatter `category:` |
| 5 | 프롬프트 | 항목 하나씩도, **카테고리째**도. 카테고리째는 **아직 넘기지 않은 대기 항목만** 담고 `sent:`를 남김 |
| 6 | 유형 | 사용 내역(수정 요청 5 · 버그 1 · 확인 요청 0, 제목이 사실상 분류)을 근거로 **제거** |
| 7 | 기존 기록 | **읽기 전용**(복사·보관·삭제만). 처리 절차도 옛 형식을 계속 읽음 |
| 8 | 미분류 | 기본 카테고리 "미분류"로 합침(파일). 브라우저에만 있던 미분류 증거는 처음 열 때 미분류 항목으로 옮김 |
| 9 | 보관·삭제 | 보관은 `items/archive/`에 로컬로 쌓임(삭제 전까지), 삭제는 md·스크린샷·편집용 원본 제거. `.pinproof/`는 git 제외 |

md 단위를 항목 하나로 정한 이유: 자동 보관이 파일 이동 하나로 끝나고, 에이전트가 항목 파일을 고치는 동안 익스텐션이 새 항목을 써도 충돌하지 않으며, 카테고리 변경이 한 줄 수정이다.

## 형식

```
.pinproof/
├ categories.json           # ["미분류", "데이터 정합성", ...] — 비어 있는 카테고리도 유지
├ items/
│  ├ 013.md                 # 항목 1개 = md 1개
│  ├ assets/013.png
│  └ archive/ (013.md, assets/013.png)
├ 001-옛-기록.md …           # 기존 기록(읽기 전용)
└ WORKFLOW.md (v5)
```

항목 md frontmatter: `id`, `category`, `status: 대기|완료`, `sent`(넘긴 시각, 선택), `created`, `updated`, `app`, `env`, `kind`, `page`, `note`.
본문은 기존 증거 섹션과 같은 내용 + `## 처리 기록`(에이전트, 익스텐션이 덮어쓰지 않음).

## 주의사항

- 익스텐션이 항목 파일을 다시 쓸 때(메모 수정·넘김 표시) 파일에 이미 `status: 완료`가 있으면 유지한다 — 에이전트 표시를 덮어쓰지 않음
- 번호는 기존 기록(`NNN-*.md`, archive 포함)과 항목(items, archive 포함)을 모두 보고 다음 번호를 매긴다
- 담기는 폴더가 연결돼 있어야 한다(미분류도 파일이 되므로)
- 다른 주소(같은 폴더에 연결)에서 만든 항목은 읽기 전용으로 보인다(편집용 원본이 주소별)
