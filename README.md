# PinProof

개발 중인 웹 화면에서 버그·정합성 문제를 **증거와 함께** 담아 프로젝트 폴더(`.pinproof/`)에 카테고리별 항목으로 쌓고, Claude Code가 `/pinproof 데이터 정합성`·`/pinproof 13`처럼 처리한 뒤 완료 표시를 남기게 하는 크롬 익스텐션입니다.

- 요소 선택(개발자도구처럼 `↑↓←→`로 부모·자식·형제 이동), 텍스트 드래그, 영역 드래그, 현재 페이지의 API 호출 목록
- 페이지 위 플로팅 툴바로 고르고, 그 자리에 뜨는 팝오버에 한 줄 메모를 써서 담음. 담을 때마다 번호(#13)가 붙은 **항목**이 되고, 요소 위에 그 번호 마커가 남음
- 항목은 직접 만든 **카테고리**(데이터 정합성, UI·UX 개선, 버그 …)에 쌓임. 에이전트가 처리를 끝내고 `status: 완료`를 남기면 패널이 알아서 보관함으로 옮김
- 프레임워크와 무관하게 동작. React(16~19)는 컴포넌트 이름과 소스 위치(`src/App.tsx:238`)를 자동으로 덧붙임
- localhost / 127.0.0.1 에서 바로 동작하고, 배포 주소 등 다른 사이트는 패널에서 **사이트별로 켜서** 씀. 외부로 아무것도 보내지 않음

설계 문서: [todo/pinproof-design.md](todo/pinproof-design.md)

## 설치 (개발 버전)

```bash
npm install
npm run build
```

1. Chrome에서 `chrome://extensions` 열기 → 오른쪽 위 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램 로드** → `.output/chrome-mv3` 폴더 선택
3. 툴바의 퍼즐 아이콘에서 PinProof를 고정(📌)

익스텐션 코드를 고친 뒤에는 `npm run build` 후 `chrome://extensions`의 PinProof 카드에서 새로고침 버튼을 누르세요.

## 사용법

1. 개발 중인 앱(`http://localhost:포트`)을 열고 툴바의 PinProof 아이콘(또는 `Alt+Shift+B`)으로 사이드 패널을 엽니다.
   - 아이콘으로 패널을 열어야 그 탭에서 **스크린샷**이 허용됩니다(Chrome의 `activeTab` 규칙). 같은 앱 안에서 페이지를 옮겨도 유지됩니다.
2. **프로젝트 폴더 연결** → 앱의 저장소 루트 폴더를 고릅니다. 만들 파일 목록을 보여주고 동의를 받습니다.
   - `.pinproof/WORKFLOW.md` (공통 처리 절차)
   - git 저장소면 `.git/info/exclude`에 `.pinproof/` 추가. 이 컴퓨터에만 적용되고 모든 워크트리가 함께 씁니다. 팀이 함께 쓰는 `.gitignore`와 프로젝트의 `.claude/commands/`는 건드리지 않습니다
   - git 워크트리 폴더(`.git`이 파일)를 고르면 무시 설정을 쓸 수 없으니, 메인 저장소의 `.git/info/exclude`에 `.pinproof/`가 있는지 확인하세요
   - `/pinproof` 커맨드는 아래 "[/pinproof 커맨드 설치](#pinproof-커맨드-설치-한-번만)"대로 개인 설정에 한 번 둡니다
3. 패널 위쪽 바구니 아이콘 옆 **담을 곳** 드롭다운에서 카테고리를 고르고(처음엔 `미분류`), 필요하면 목록 맨 아래 **+ 새 카테고리**로 만듭니다(예: 데이터 정합성, UI·UX 개선, 버그). 고른 카테고리는 주소마다 기억합니다. 목록의 줄마다 있는 연필(**이름 바꾸기**)은 그 카테고리의 항목까지 함께 바꾸고, 휴지통(**삭제**)은 빈 카테고리면 바로 지우고, 대기 항목이 있으면 한 번 묻고 그 항목까지 함께 지웁니다(보관함 항목은 남음). 항목이 없는 카테고리는 **프롬프트 복사**가 꺼져 있습니다.
   - 패널이 열려 있는 동안 앱 화면 **아래 가운데에 툴바**가 뜹니다(패널을 닫으면 사라짐). 오른쪽 칩에 지금 카테고리와 대기 항목 수(`데이터 정합성 · 대기 3`)가 보입니다. 왼쪽 손잡이를 잡아 끌어 옮길 수 있고, 옮긴 위치는 앱마다 기억합니다.
   - 모드에 들어가면 툴바가 그 모드의 안내 띠로 바뀌고 핀 로고가 숨 쉽니다. 담아도 모드는 계속되며, `Esc`로 끝냅니다.
   - 모드 중에 안내 띠 왼쪽의 모드 이름(예: **● 영역 ▴**)을 누르면 선택 메뉴가 열려, 모드를 끄지 않고 요소·텍스트·영역으로 바로 바꾸거나 네트워크를 담을 수 있습니다. 메뉴가 열려 있을 때 `Esc`·바깥 클릭은 메뉴만 닫습니다.

| 툴바 버튼 | 단축키 (페이지에서) | 동작 |
|---|---|---|
| 요소 | `Alt+Shift+E` | hover로 고르고 클릭/Enter. `↑` 부모, `↓` 자식, `←→` 형제 |
| 텍스트 | `Alt+Shift+T` | 글자를 드래그해 놓기 |
| 영역 | `Alt+Shift+R` | 사각형을 그리기. 안쪽 요소 목록도 함께 기록 |
| 네트워크 | `Alt+Shift+N` | 현재 route에서 호출된 API(상태·크기·응답 앞 500자)를 바로 담기. 요청 헤더·쿠키는 기록하지 않음 |
| 마커 숨기기 | `Alt+Shift+H` | 페이지 위 마커를 잠시 숨기기/보이기 |

   - 요소 모드에서 **Alt를 누르는 동안 페이지를 조작**할 수 있습니다. Alt를 누른 채 메뉴를 열고 항목 위로 마우스를 옮긴 다음, Alt를 놓고 클릭하면 그 항목을 담습니다. Hover로만 보이는 메뉴도 툴바로 돌아가지 않고 같은 방식으로 고를 수 있습니다.
   - 브라우저 기본 모달과 팝오버가 열린 상태에서도 툴바와 메모창을 사용할 수 있습니다. 페이지 팝오버 안의 항목을 담을 때 툴바 클릭이나 메모 입력 때문에 팝오버가 닫히지 않습니다.
   - 네트워크 기록은 경로뿐 아니라 쿼리와 해시도 구분합니다. `?tab=one`과 `?tab=two`에서 호출한 API를 각각의 화면에 담고, 응답이 늦게 도착해도 요청을 시작한 화면에 기록합니다.
   - 파일 저장에 실패한 자료는 패널의 **저장 대기** 목록에 남습니다. 패널을 닫았다 열어도 이 브라우저에 보관되며, **저장 다시 시도**로 프로젝트 파일에 쓸 수 있습니다. 아직 저장하지 못한 자료도 항목 번호를 따로 사용합니다. 카테고리를 삭제해도 아직 파일로 저장하지 못한 새 자료는 **미분류**에 남습니다.

   - 요소·텍스트·영역을 고르면 **그 자리에 팝오버**가 뜹니다. 머리에 요소 이름·컴포넌트·소스 위치와 담길 곳(`13 데이터 정합성`)이 보입니다. 한 줄 메모를 쓰고 `Enter`(메모 없이도 됨), 그만두려면 `Esc`나 바깥 클릭. 담으려면 프로젝트 폴더가 연결돼 있어야 합니다.
   - 담은 항목은 요소 위 테두리에 **검은(다크 테마에선 흰) 번호 마커**로 꽂힙니다. 마커는 담은 화면과 주소가 같을 때만 보입니다(`?tab=`처럼 쿼리만 바뀐 화면에서도 숨김). 마커에 마우스를 올리면 번호·카테고리·메모가, 누르면 메모 수정·삭제 팝오버가 뜹니다.
   - 같은 요소를 다시 고르면 새로 담지 않고 그 마커의 편집 팝오버를 엽니다.
   - 사이드 패널에는 카테고리마다 상자가 있고, 항목이 한 줄씩(`13 <strong> "10" · 메모`) 쌓입니다. 담는 중인 카테고리는 진한 테두리로 맨 위에, 나머지는 항목이 있을 때만 그 아래에 보입니다(상자 머리의 **여기에 담기**로 바꿀 수 있음). 줄을 누르면 펼쳐지고(한 번에 하나), 지금 페이지에 있는 항목이면 그 마커가 반짝입니다. 네트워크·붙여넣기처럼 페이지 마커가 없는 항목은 번호 원이 테두리만 있습니다. 잘못 담았으면 줄 오른쪽 **✕**로 지웁니다(한 번 확인).
   - 항목을 펼치면 **해당 페이지로 이동 ↗**(그 화면으로 가서 마커를 반짝임), **프롬프트 복사**(이 항목만), 오른쪽 **카테고리 선택 + [이동]**(다른 카테고리로 옮기기)이 있습니다.
   - 다른 곳에서 찍은 스크린샷·복사한 로그는 담는 중인 카테고리의 **붙여넣기 칸**을 클릭하고 `⌘V`(또는 이미지 드래그 앤 드롭). 패널의 입력칸 밖에서 `⌘V` 해도 담깁니다.
4. 테이블처럼 여러 행이 있는 값은 셀을 잡고 `↑`로 테이블/컨테이너까지 올라가 담으면, 헤더·보이는 행 수·컴포넌트 위치가 기록됩니다. 합계 비교 같은 판단은 Claude가 코드와 API를 직접 추적해서 합니다.
5. 카테고리 상자 머리의 **프롬프트 복사 (새 n)** 은 그 카테고리에서 **아직 넘기지 않은 대기 항목만** 담아 복사하고, 넘긴 항목에는 **넘김** 표시(md 의 `sent:`)를 남깁니다. 그래서 "앞에 보낸 건 빼고 처리해줘"라고 따로 말할 필요가 없습니다. 모두 넘긴 뒤에는 **프롬프트 다시 복사**(대기 항목 전부)로 바뀝니다.

### 배포 주소에서 쓰기 (사이트별로 켜기)

`http://192.168.0.92:20100` 같은 배포 주소에서 화면을 보며 기록하고, 기록은 로컬 프로젝트 폴더에 쌓아 로컬 에이전트가 처리하게 할 수 있습니다. 스토어 배포는 필요 없습니다.

1. 그 주소의 탭에서 패널을 열고 **이 사이트에서 PinProof 켜기** → Chrome 권한 확인에서 허용 → 탭이 새로고침되며 툴바가 뜹니다
2. **프로젝트 폴더 연결**에서 로컬 저장소(예: `sc-cloud-ocp`)를 고릅니다. localhost 와 같은 폴더에 연결해도 되고, 항목 번호와 카테고리 목록은 폴더 기준으로 함께 씁니다
3. 담은 항목의 md 에는 `env: deployed`가 붙고, 처리 절차(WORKFLOW)는 배포 항목을 이렇게 다룹니다: 소스 위치 대신 화면 글자·selector·API 경로로 코드를 찾고, 배포 버전과 로컬 코드의 차이를 먼저 확인
4. 끄려면 연결 줄 아래 **직접 켠 사이트입니다 · 끄기**(권한을 회수하고 탭을 새로고침)

- 배포 빌드는 소스맵·React 개발 정보가 없어 소스 위치·컴포넌트 이름이 비거나 압축될 수 있습니다. 요소·텍스트·영역·스크린샷·네트워크는 그대로 동작합니다
- 카테고리 상자에는 지금 탭의 주소에서 담은 항목만 보입니다. 같은 폴더에 연결한 다른 주소의 대기 항목은 아래 **다른 주소 항목**에 접혀 있고, 펼치면 만든 주소와 함께 읽기만 됩니다(메모 수정·옮기기·삭제는 그 주소 탭에서)

### 다크 모드

기본은 시스템 설정(라이트·다크)을 따릅니다. 사이드 패널 머리 줄 오른쪽의 테마 버튼을 누를 때마다 **시스템 설정 → 라이트 → 다크** 순으로 바뀌고, 고른 값은 기억됩니다. 페이지 위 툴바·팝오버·마커도 같은 테마를 따릅니다.

화면은 무채색입니다(잉크·종이 두 색의 농도만, `lib/tokens.css`). 오류·경고도 빨강·주황 대신 반전 배지·굵은 글자로 보입니다. 하이라이트와 마커는 검정·흰색 두 겹 선이라 밝은 페이지와 어두운 페이지 모두에서 보입니다.

### /pinproof 커맨드 설치 (한 번만)

커맨드는 프로젝트가 아니라 개인 설정(`~/.claude/commands/`)에 둡니다. 팀 저장소에 흔적이 남지 않고, 어느 프로젝트·워크트리에서든 `.pinproof/`가 있으면 동작합니다.

```bash
mkdir -p ~/.claude/commands && printf '%s\n' '---' 'description: PinProof 대기 항목 목록 보기(인자 없음) 또는 처리(카테고리 이름 · 항목 번호)' 'argument-hint: "[카테고리 | 번호...]"' '---' '' '`.pinproof/WORKFLOW.md`를 읽고 그 절차를 그대로 따른다. 지금 폴더에 `.pinproof/`가 없으면 `git worktree list` 첫 줄(메인 워크트리)의 `.pinproof/`를 쓰고, 코드 수정은 지금 폴더에서 한다.' '' '인자: $ARGUMENTS' > ~/.claude/commands/pinproof.md
```

예전 버전으로 연결한 프로젝트에는 `.claude/commands/pinproof.md`와 `.gitignore`의 `# PinProof` 블록이 남아 있을 수 있습니다. 익스텐션은 이것들을 지우지 않습니다(팀 파일일 수 있어서). 필요 없으면 직접 지우고 `.git/info/exclude`에 `.pinproof/`를 넣으세요.

### Claude Code에 넘기기

```text
/pinproof                  # 대기 항목을 카테고리별로 보기
/pinproof 데이터 정합성     # 그 카테고리의 대기 항목을 하나씩 처리
/pinproof 13 14            # 13·14번 항목 처리 (옛 기록 번호도 됨)
```

claude.ai나 다른 에이전트에는 패널의 **프롬프트 복사**로 붙여넣으세요. 프롬프트에는 넘길 항목 파일(`.pinproof/items/013.md` …)이 하나하나 적혀 있고, 에이전트는 적힌 항목만 처리합니다. 항목은 일반 Markdown이라 어떤 에이전트든 읽을 수 있습니다.

에이전트는 항목을 처리하면 그 파일 끝에 `## 처리 기록`을 남기고 frontmatter `status: 대기`를 `status: 완료`로 바꿉니다(사용자 답을 기다리는 등 끝나지 않았으면 `대기`로 둠). 패널은 5초마다 이를 확인해 **완료 항목을 보관함(`items/archive/`)으로 바로 옮기고** 알려 줍니다. 화면에서 확인해 보니 덜 고쳐졌으면 **보관함 → 되돌리기**로 다시 대기 항목으로 돌립니다(처리 기록은 남고, 다음 처리 때 재처리로 다룹니다).

**git 워크트리에서 처리할 때**: 항목은 폴더를 연결한 메인 워크트리의 `.pinproof/`에만 있습니다. `/pinproof`와 **프롬프트 복사** 문구, 처리 절차는 모두 "지금 폴더에 `.pinproof/`가 없으면 `git worktree list` 첫 줄(메인 워크트리)의 `.pinproof/`를 읽고, 코드 수정은 지금 폴더에서"를 따르므로 어느 워크트리의 세션에 보내도 됩니다. (익스텐션은 브라우저 보안상 연결한 폴더의 절대 경로를 알 수 없어 경로 대신 이 규칙을 씁니다.)

보관한 항목은 지우기 전까지 `.pinproof/items/archive/`에 남습니다. 필요 없는 항목은 대기 목록의 **✕** 나 보관함의 **삭제**(확인 창)로 지웁니다. md와 스크린샷이 지워지며 되돌릴 수 없습니다. `.pinproof/`는 `.git/info/exclude`로 git 에서 빠져 있어 어디에도 올라가지 않습니다.

**카테고리 이전의 기록**(`012-제목.md`, 기록 1건에 증거 A·B·C)은 패널 아래 **이전 기록**에 읽기 전용으로 남습니다(복사·보관·삭제만). 처리 절차도 옛 형식을 계속 읽습니다.

### 처리 절차(WORKFLOW.md) 업데이트

익스텐션이 새 버전의 처리 절차를 갖고 있으면 패널 위쪽에 **처리 절차 새 버전 · [업데이트]**가 뜹니다. 누르면 `.pinproof/WORKFLOW.md`가 교체됩니다(자동으로 바꾸지 않음). 프로젝트마다 덧붙일 규칙은 `.pinproof/WORKFLOW.local.md`에 쓰세요. 익스텐션이 건드리지 않고, WORKFLOW가 함께 따르도록 안내합니다.

### 이전 이름(BugNotes)에서 옮겨오기

예전 버전으로 만든 `.bugnotes/` 폴더가 있는 프로젝트는 폴더를 연결할 때 확인 목록에 "옮기기"가 함께 표시되고, 이미 연결된 경우 패널에 **[옮기기]** 버튼이 뜹니다. 기록·스크린샷·보관함을 `.pinproof/`로 복사하고(덮어쓰지 않음), 모두 옮기면 `.bugnotes/`와 `/bugnotes` 커맨드를 지우고 `.git/info/exclude`에 `.pinproof/`를 넣습니다(`.gitignore`의 옛 `# BugNotes` 줄은 건드리지 않음).

## 저장 구조

```
프로젝트/
├ .pinproof/
│  ├ WORKFLOW.md
│  ├ categories.json                # ["미분류", "데이터 정합성", …] 비어 있는 카테고리도 유지
│  ├ items/
│  │  ├ 013.md                      # 항목 1개 = md 1개 (category·status·sent 는 frontmatter)
│  │  ├ assets/013.png
│  │  └ archive/                    # 완료되어 보관된 항목 (013.md, assets/013.png)
│  ├ 012-대시보드-총합-불일치.md     # 카테고리 이전의 옛 기록 (읽기 전용)
│  ├ assets/012/A.png …
│  └ archive/
└ .git/info/exclude                 # ".pinproof/" 한 줄 (내 컴퓨터에만)

~/.claude/commands/pinproof.md      # /pinproof 커맨드 (개인 설정)
```

- md의 `## 처리 기록` 아래는 익스텐션이 절대 덮어쓰지 않습니다. 메모를 고치거나 카테고리를 옮겨 항목을 다시 써도 처리 기록은 남고, 파일에 이미 `status: 완료`가 있으면 그대로 둡니다.
- 항목 번호는 폴더 전체에서 이어집니다(옛 기록 번호 다음부터).
- 항목의 메모 수정·옮기기는 그 항목을 만든 브라우저·주소에서만 됩니다(편집용 원본을 브라우저 IndexedDB에 둡니다).

## 개발

```bash
npm test          # 단위 테스트 (vitest)
npm run compile   # 타입 검사
npm run test:e2e  # Playwright Chromium에 익스텐션을 로드해 끝까지 검증
node tests/e2e/run.mjs http://localhost:5190/   # React 앱 dev 서버가 떠 있으면 React 어댑터까지 검증
```

E2E는 폴더 선택 창과 툴바 아이콘 클릭을 자동화할 수 없어, 익스텐션 OPFS를 프로젝트 폴더 대신 쓰고(`?opfs=1`) 테스트 빌드에만 `<all_urls>`를 넣어 스크린샷을 허용합니다.

### 알려진 제약

- 소스 위치: React 19는 소스맵으로 원본 줄을 복원합니다. 빌드 플러그인이 소스맵을 잇지 않는 경우(예: StyleX)는 Vite의 `?raw`로 실제 파일과 대조해 요소의 속성으로 줄을 다시 찾고, 찾지 못하면 "근처"로 표시합니다.
- 가상 스크롤 목록은 화면에 보이는 행만 DOM에 있으므로 "보이는 행 수"는 전체가 아닐 수 있습니다(WORKFLOW.md가 Claude에게 데이터 출처로 확인하라고 안내).
- Chrome 사이드 패널에서 폴더 선택 창이 막히는 환경이면 자동으로 별도 탭(`connect.html`)에서 고르게 합니다.
