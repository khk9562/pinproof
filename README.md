# PinProof

개발 중인 웹 화면에서 버그·정합성 문제를 **증거와 함께** 기록해 프로젝트 폴더(`.pinproof/`)에 쌓고, Claude Code가 `/pinproof 12`로 건별 처리하게 하는 크롬 익스텐션입니다.

- 요소 선택(개발자도구처럼 `↑↓←→`로 부모·자식·형제 이동), 텍스트 드래그, 영역 드래그, 현재 페이지의 API 호출 목록
- 페이지 위 플로팅 툴바로 고르고, 그 자리에 뜨는 팝오버에 한 줄 메모를 써서 담음. 담은 증거는 요소 위에 A·B·C 핀 마커로 남음
- 페이지를 옮겨도 "작성 중인 기록"에 증거가 계속 쌓임
- 프레임워크와 무관하게 동작. React(16~19)는 컴포넌트 이름과 소스 위치(`src/App.tsx:238`)를 자동으로 덧붙임
- localhost / 127.0.0.1 에서만 동작, 외부로 아무것도 보내지 않음

설계 문서: [todo/pinproof-design.md](todo/pinproof-design.md)

## 설치 (개발 버전)

```bash
npm install
npm run build
```

1. Chrome에서 `chrome://extensions` 열기 → 오른쪽 위 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램 로드** → `.output/chrome-mv3` 폴더 선택
3. 툴바의 퍼즐 아이콘에서 PinProof를 고정(📌)

익스텐션 코드를 고친 뒤에는 `npm run build` 후 `chrome://extensions`의 PinProof 카드에서 새로고침 버튼을 누르세요.

## 사용법

1. 개발 중인 앱(`http://localhost:포트`)을 열고 툴바의 PinProof 아이콘(또는 `Alt+Shift+B`)으로 사이드 패널을 엽니다.
   - 아이콘으로 패널을 열어야 그 탭에서 **스크린샷**이 허용됩니다(Chrome의 `activeTab` 규칙). 같은 앱 안에서 페이지를 옮겨도 유지됩니다.
2. **프로젝트 폴더 연결** → 앱의 저장소 루트 폴더를 고릅니다. 만들 파일 목록을 보여주고 동의를 받습니다.
   - `.pinproof/WORKFLOW.md` (공통 처리 절차)
   - git 저장소면 `.git/info/exclude`에 `.pinproof/` 추가. 이 컴퓨터에만 적용되고 모든 워크트리가 함께 씁니다. 팀이 함께 쓰는 `.gitignore`와 프로젝트의 `.claude/commands/`는 건드리지 않습니다
   - git 워크트리 폴더(`.git`이 파일)를 고르면 무시 설정을 쓸 수 없으니, 메인 저장소의 `.git/info/exclude`에 `.pinproof/`가 있는지 확인하세요
   - `/pinproof` 커맨드는 아래 "[/pinproof 커맨드 설치](#pinproof-커맨드-설치-한-번만)"대로 개인 설정에 한 번 둡니다
3. **+ 새 기록** → 제목·유형·연관·메모를 쓰고 증거를 담습니다.
   - 패널이 열려 있는 동안 앱 화면 **오른쪽 위에 툴바**가 뜹니다(패널을 닫으면 사라짐). 왼쪽 손잡이를 잡아 끌어 옮길 수 있고, 옮긴 위치는 앱마다 기억합니다.
   - 모드에 들어가면 툴바가 그 모드의 안내 띠로 바뀌고 핀 로고가 숨 쉽니다. 담아도 모드는 계속되며, `Esc`로 끝냅니다.

| 툴바 버튼 | 단축키 (페이지에서) | 동작 |
|---|---|---|
| 요소 | `Alt+Shift+E` | hover로 고르고 클릭/Enter. `↑` 부모, `↓` 자식, `←→` 형제 |
| 텍스트 | `Alt+Shift+T` | 글자를 드래그해 놓기 |
| 영역 | `Alt+Shift+R` | 사각형을 그리기. 안쪽 요소 목록도 함께 기록 |
| 네트워크 | `Alt+Shift+N` | 현재 route에서 호출된 API(상태·크기·응답 앞 500자)를 바로 담기. 요청 헤더·쿠키는 기록하지 않음 |
| 마커 숨기기 | `Alt+Shift+H` | 페이지 위 마커를 잠시 숨기기/보이기 |

   - 요소·텍스트·영역을 고르면 **그 자리에 팝오버**가 뜹니다. 머리에 요소 이름·컴포넌트·소스 위치와 담길 곳(`A #012`, 작성 중 기록이 없으면 `미분류`)이 보입니다. 한 줄 메모를 쓰고 `Enter`(메모 없이도 됨), 그만두려면 `Esc`나 바깥 클릭.
   - 담은 증거는 요소 위 테두리에 **하늘색 A·B·C 마커**로 꽂힙니다(미분류는 회색 점). 마커는 담은 화면과 주소가 같을 때만 보입니다(`?tab=`처럼 쿼리만 바뀐 화면에서도 숨김). 마커에 마우스를 올리면 메모가, 누르면 메모 수정·삭제·미분류↔기록 옮기기 팝오버가 뜹니다.
   - 같은 요소를 다시 고르면 새로 담지 않고 그 마커의 편집 팝오버를 엽니다.
   - 사이드 패널에는 증거가 한 줄씩(`A <strong> "10" · 메모`) 쌓입니다. 줄을 누르면 펼쳐지고, 지금 페이지에 있는 증거면 그 마커가 반짝입니다. 네트워크·붙여넣기처럼 페이지 마커가 없는 증거는 문자 원이 테두리만 있습니다. 잘못 담았으면 줄 오른쪽 **✕**로 지웁니다.
   - 다른 곳에서 찍은 스크린샷·복사한 로그는 작성 중 기록의 **붙여넣기 칸**을 클릭하고 `⌘V`(또는 이미지 끌어다 놓기). 패널의 입력칸 밖에서 `⌘V` 해도 담깁니다.
4. 테이블처럼 여러 행이 있는 값은 셀을 잡고 `↑`로 테이블/컨테이너까지 올라가 담으면, 헤더·보이는 행 수·컴포넌트 위치가 기록됩니다. 합계 비교 같은 판단은 Claude가 코드와 API를 직접 추적해서 합니다.
5. 다 모았으면 **작성 종료**. 작성 중인 기록이 없을 때 담은 증거는 **미분류**에 모였다가 나중에 기록으로 옮길 수 있습니다.

### 다크 모드

기본은 시스템 설정(라이트·다크)을 따릅니다. 사이드 패널 머리 줄 오른쪽의 테마 버튼을 누를 때마다 **시스템 설정 → 라이트 → 다크** 순으로 바뀌고, 고른 값은 기억됩니다. 페이지 위 툴바·팝오버·마커도 같은 테마를 따릅니다.

### /pinproof 커맨드 설치 (한 번만)

커맨드는 프로젝트가 아니라 개인 설정(`~/.claude/commands/`)에 둡니다. 팀 저장소에 흔적이 남지 않고, 어느 프로젝트·워크트리에서든 `.pinproof/`가 있으면 동작합니다.

```bash
mkdir -p ~/.claude/commands && printf '%s\n' '---' 'description: PinProof 기록 건 목록 보기(인자 없음) 또는 처리(번호)' 'argument-hint: "[기록 번호]"' '---' '' '`.pinproof/WORKFLOW.md`를 읽고 그 절차를 그대로 따른다. 지금 폴더에 `.pinproof/`가 없으면 `git worktree list` 첫 줄(메인 워크트리)의 `.pinproof/`를 쓰고, 코드 수정은 지금 폴더에서 한다.' '' '인자: $ARGUMENTS' > ~/.claude/commands/pinproof.md
```

예전 버전으로 연결한 프로젝트에는 `.claude/commands/pinproof.md`와 `.gitignore`의 `# PinProof` 블록이 남아 있을 수 있습니다. 익스텐션은 이것들을 지우지 않습니다(팀 파일일 수 있어서). 필요 없으면 직접 지우고 `.git/info/exclude`에 `.pinproof/`를 넣으세요.

### Claude Code에 넘기기

```text
/pinproof        # 보관 안 된 기록 목록
/pinproof 12     # 12번 기록을 읽고 원인 분석 → (버그·수정 요청이면) 수정 → 파일 끝에 "## 처리 기록" 추가
```

claude.ai나 다른 에이전트에는 패널의 **복사** 버튼으로 프롬프트를 붙여넣으세요. 기록은 일반 Markdown이라 어떤 에이전트든 읽을 수 있습니다.

**git 워크트리에서 처리할 때**: 기록은 폴더를 연결한 메인 워크트리의 `.pinproof/`에만 있습니다. `/pinproof 12`와 **복사** 문구, 처리 절차(WORKFLOW v3)는 모두 "지금 폴더에 `.pinproof/`가 없으면 `git worktree list` 첫 줄(메인 워크트리)의 `.pinproof/`를 읽고, 코드 수정은 지금 폴더에서"를 따르므로 어느 워크트리의 세션에 보내도 됩니다. (익스텐션은 브라우저 보안상 연결한 폴더의 절대 경로를 알 수 없어 경로 대신 이 규칙을 씁니다.) 기존 프로젝트는 패널의 **처리 절차 새 버전 · [업데이트]** 를 눌러 v3로 바꾸고, 개인 커맨드도 위 설치 명령으로 다시 만드세요.

화면에서 수정이 확인되면 목록의 **보관**을 누릅니다. md와 스크린샷이 `.pinproof/archive/`로 옮겨지고(삭제 안 함) `/pinproof` 목록에서 빠집니다.

필요 없는 기록은 목록의 **삭제**(작성 중이면 카드 아래 **기록 삭제**)로 지웁니다. 확인 창을 거쳐 md와 스크린샷이 프로젝트 폴더에서 지워지며 되돌릴 수 없습니다. 나중에 다시 볼 수도 있으면 보관을 쓰세요.

### 처리 절차(WORKFLOW.md) 업데이트

익스텐션이 새 버전의 처리 절차를 갖고 있으면 패널 위쪽에 **처리 절차 새 버전 · [업데이트]**가 뜹니다. 누르면 `.pinproof/WORKFLOW.md`가 교체됩니다(자동으로 바꾸지 않음). 프로젝트마다 덧붙일 규칙은 `.pinproof/WORKFLOW.local.md`에 쓰세요. 익스텐션이 건드리지 않고, WORKFLOW가 함께 따르도록 안내합니다.

### 이전 이름(BugNotes)에서 옮겨오기

예전 버전으로 만든 `.bugnotes/` 폴더가 있는 프로젝트는 폴더를 연결할 때 확인 목록에 "옮기기"가 함께 표시되고, 이미 연결된 경우 패널에 **[옮기기]** 버튼이 뜹니다. 기록·스크린샷·보관함을 `.pinproof/`로 복사하고(덮어쓰지 않음), 모두 옮기면 `.bugnotes/`와 `/bugnotes` 커맨드를 지우고 `.git/info/exclude`에 `.pinproof/`를 넣습니다(`.gitignore`의 옛 `# BugNotes` 줄은 건드리지 않음).

## 저장 구조

```
프로젝트/
├ .pinproof/
│  ├ WORKFLOW.md
│  ├ 012-대시보드-총합-불일치.md     # 기록 1건 = md 1개
│  ├ assets/012/A.png …
│  └ archive/
└ .git/info/exclude                 # ".pinproof/" 한 줄 (내 컴퓨터에만)

~/.claude/commands/pinproof.md      # /pinproof 커맨드 (개인 설정)
```

- md의 `## 처리 기록` 아래는 익스텐션이 절대 덮어쓰지 않습니다. 기록을 다시 열어 증거를 추가해도 Claude의 처리 기록은 남습니다.
- 기록을 다시 열어 편집하는 것은 그 기록을 만든 브라우저에서만 됩니다(편집용 원본을 브라우저 IndexedDB에 둡니다).

## 개발

```bash
npm test          # 단위 테스트 (vitest)
npm run compile   # 타입 검사
npm run test:e2e  # Playwright Chromium에 익스텐션을 로드해 끝까지 검증
node tests/e2e/run.mjs http://localhost:5190/   # React 앱 dev 서버가 떠 있으면 React 어댑터까지 검증
```

E2E는 폴더 선택 창과 툴바 아이콘 클릭을 자동화할 수 없어, 익스텐션 OPFS를 프로젝트 폴더 대신 쓰고(`?opfs=1`) 테스트 빌드에만 `<all_urls>`를 넣어 스크린샷을 허용합니다.

### 알려진 제약

- 소스 위치: React 19는 소스맵으로 원본 줄을 복원합니다. 빌드 플러그인이 소스맵을 잇지 않는 경우(예: StyleX)는 Vite의 `?raw`로 실제 파일과 대조해 요소의 속성으로 줄을 다시 찾고, 찾지 못하면 "근처"로 표시합니다.
- 가상 스크롤 목록은 화면에 보이는 행만 DOM에 있으므로 "보이는 행 수"는 전체가 아닐 수 있습니다(WORKFLOW.md가 Claude에게 데이터 출처로 확인하라고 안내).
- Chrome 사이드 패널에서 폴더 선택 창이 막히는 환경이면 자동으로 별도 탭(`connect.html`)에서 고르게 합니다.
